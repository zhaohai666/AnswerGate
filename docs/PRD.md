## 1. 原始需求复述

开发一个本地独立控制台程序 **AnswerGate**：孩子必须答对一定数量的题目（按学段/学科分层抽题、判分），达到及格线后程序才代为启动指定的目标软件（游戏/视频 App），随后自身退出。家长可配置白名单软件、重试次数、冷却时间；答题行为记录本地日志；题库本地 JSON、离线优先；一次打包产出 Windows(.exe)、macOS(.app)、Android(.apk) 三端，统一 GUI 答题界面，无 CLI。

---

## 2. 产品目标（Product Goals）

1. **实现"答题解锁"核心闭环**：孩子完成抽题→作答→判分流程，正确率达标后自动启动白名单目标软件并退出，全程无家长值守、三端体验一致。
2. **提供可靠的家长管控能力**：白名单配置、重试次数、冷却时间等管控状态由 Rust 侧持久化，防止重启/删配置绕过；答题日志完整可查。
3. **离线优先、隐私安全**：题库与配置全部本地存储，默认零联网、零数据上传；题库 JSON 格式简单，家长可自行增删改。
4. **儿童友好的操作体验**：大按钮、大字体、清晰反馈动效，学龄前至初中孩子可独立完成答题，触屏/鼠标/键盘均可操作。
5. **一次开发，三端交付**：一套代码产出 Windows / macOS / Android 安装包，Android 端针对触屏与输入特性做适配。

## 5. UI 设计稿（文字描述，三端共用）

### 5.1 整体设计原则

- **儿童友好**：大按钮（≥64px 高）、大字体（正文 ≥20px）、高对比配色、圆角卡片。
- **单任务流**：全程线性"选学段 → 答题 → 结果/冷却"，无多余入口；三端共用同一套 Svelte 组件，Android 端竖屏布局微调。
- **状态权威在 Rust**：前端仅展示，重试/冷却倒计时由 Rust 侧事件驱动，页面刷新不重置。

### 5.2 页面清单与状态机

```
学段选择页 → 答题页 → 结果页 ─┬─ 通过 → [启动动画] → 程序退出
                              └─ 失败 → 「再试一次」→ 答题页
                                        └─ 重试耗尽 → 冷却页 → 倒计时结束 → 答题页
```

### 5.3 各页面元素与交互

**① 学段选择页（LevelSelect）**
- 元素：应用 Logo 与标题"AnswerGate 答题门禁"；三张大卡片按钮（幼儿园 / 小学 / 初中），每张卡片配图标与一句话说明；底部小字显示本次规则摘要（抽 N 题、及格线 xx%）。
- 交互：点击卡片 → 调用 `start_quiz` 进入答题页；Android 端卡片纵向排列占满屏宽。

**② 答题页（QuizPage）**
- 元素：顶部进度条与"第 x / N 题"；题干大字居中；按题型渲染作答区——单选：选项大按钮列表；判断：对 ✓ / 错 ✗ 两个大按钮；填空：大号输入框 + 确认按钮；底部"上一题/下一题"导航；答错提交后选项抖动 + 短提示动效。
- 交互：选择/输入后点"下一题"；最后一题提交后调用 `get_result` 进入判分；移动端自动隐藏填空输入（抽题已过滤）。

**③ 结果页（ResultPage）**
- 通过态：大号 ✅ + "校验通过，即将启动 {目标软件名}"；3 秒倒计时动画 → 调用 `launch_target` → 显示"已启动，本程序即将关闭" → 自动退出；启动失败时显示具体错误（如路径不存在）并提供"重试启动/返回首页"。
- 失败态：大号 ❌ + 本次得分与及格线对比；剩余重试次数；「再试一次」大按钮（重新抽题进入答题页）；重试耗尽时该按钮替换为"进入冷却"并自动跳转冷却页。

**④ 冷却页（CooldownPage）**
- 元素：大号 ⏳ 与圆形倒计时（由 Rust 侧事件推送剩余秒数，前端不可篡改）；说明文案"休息一下，稍后再来答题"；倒计时归零自动跳转答题页。
- 边界：重启程序后读取持久化冷却状态，若仍在冷却中直接进入本页（防绕过）。

### 5.4 平台差异要点

| 平台 | 适配点 |
|---|---|
| Windows / macOS | 键盘可用（数字键选选项、回车提交）；窗口固定合理尺寸（约 800×600），居中显示 |
| Android | 竖屏布局；填空题过滤；返回键在答题页拦截并确认（防误退）；系统状态栏适配 |

## 7. 验收要点（摘要）

1. 三端各一台真机完整走通"选学段 → 答题 → 判分 → 启动目标软件 → 自动退出"。
2. 重试耗尽进入冷却后，重启程序冷却状态不重置；删除配置文件亦不能重置（P0-06 验收）。
3. 题库 JSON 全部通过 schema 校验，无重复 id，非法格式报错友好。
4. 非技术家长按 README 可独立完成：改白名单、调及格线、替换题库。
5. `cargo test` + 前端 lint/tsc 全绿；状态机全路径（PASS / FAIL→RETRY / RETRY耗尽→COOLDOWN）有测试覆盖。
