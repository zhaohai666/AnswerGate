## 1. 增量背景与推翻项

用户原始需求：
> 「需要指定比如哔哩哔哩的软件打开以后需要持续检查观看时间，如果时间超过配置的比如10分钟，那就需要答题才能继续查看」「没有指定那个软件可以打开和关闭」

**v1 模式被推翻的两点：**

1. **推翻 v1 Q6 决策「不做常驻监控」**：v1 是"答题→启动软件→AnswerGate 退出"的一次性门禁；v2 改为 **AnswerGate 常驻运行**，在目标软件使用期间持续计时监控。
2. **推翻 v1 P0-05「解锁成功后程序自动退出」**：桌面端 AnswerGate 启动目标软件后**不再退出**，而是转入"使用中监控状态"，负责纳管目标软件进程的生命周期（计时→超时→关闭→答题→续期拉起）。

**新核心闭环（轮次制）**：AnswerGate 启动目标软件 → 计时 `use_minutes` → 到点关闭目标软件并把答题界面带回前台 → 答题通过则解锁下一轮（重新拉起，再计 `use_minutes`）→ 答错/不答则保持关闭，走既有重试/冷却机制。

**能力边界（沿用 v1 声明，不扩大承诺）**：本方案仍是**应用层门禁**。仅对"由 AnswerGate 启动并被纳管"的进程生效；孩子若绕开程序自行点开目标软件，v2 无法拦截（macOS/Windows 无法应用层强拦截）。管控边界话术与 README 13.5 保持一致。

### 监控模式与应用层门禁边界说明（必读）

- **能管**：AnswerGate 自己拉起的目标软件进程 —— 可计时、可 kill、可续期拉起。
- **不能管**：孩子绕开 AnswerGate 手动打开的目标软件 —— 无法检测计时、无法拦截（桌面端无系统级 HOOK；Android 端甚至无法 kill 其他应用，见 Q3 降级方案）。
- 说法统一为：*"AnswerGate 是回合制使用教练，不是系统级防火墙"*；强管控仍建议配合系统家长控制（README 13.5）。

> 📌 **该边界已被 v3 推翻（桌面端）**：v3 新增独立进程监控（watchdog），能发现并拦截「绕开门禁手动打开」的白名单目标（见 `docs/PRD-v3-incremental.md`）。
> 同时 v3 把 pause 模式改为「只暂停、不删除」，超时续期卷改为 3 题全对。

## 4. UI 增量（三端共用，沿用 v1 设计语言）

### 4.1 新增/变更页面

**⑤ 使用中状态页（MonitoringPage）— 新增**
- 元素：目标软件名 + 图标；本轮剩余时间**大号倒计时**（mm:ss，Rust 侧驱动）；已完成轮次"N 轮"；「提前结束本轮」小按钮（灰色，防误触需二次确认）。
- 交互：倒计时归零 → 自动进入超时答题触发过渡；用户提前结束 → 回到学段/目标选择页；P1-08 预警态最后 60 秒整体变红。

**⑥ 超时答题过渡页（TimeoutGatePage）— 新增**
- 时序：kill 目标软件 → AnswerGate 强制置顶带回前台 → 显示"时间到！{软件名} 已暂停"大字提示（3 秒）→ 自动进入既有答题页。
- 复用 v1 答题页/结果页/冷却页，无改动；仅结果页通过态文案变更：

**③' 结果页（通过态，变更）**
- v1："校验通过，即将启动 XX" → v2 超时续期场景："答对啦！再给你 10 分钟，正在打开 {软件名}…" → 调用续期拉起 → 跳回使用中状态页。**AnswerGate 不退出**。

### 4.2 状态机增量

```
v1: IDLE → QUIZ → (PASS → LAUNCH → EXIT) | (FAIL → RETRY / COOLDOWN)
v2: IDLE → QUIZ → PASS → LAUNCH → MONITORING(使用中,计时)
      MONITORING → 超时 → KILL + TIMEUP_GATE → QUIZ(超时答题)
        → PASS → RELAUNCH → MONITORING（新一轮）
        → FAIL → RETRY/COOLDOWN → …（目标软件保持关闭）
      MONITORING → 用户提前结束 / 进程意外退出 → IDLE
```

## 5. 验收要点（真实端到端）

> ✅ = 已由自动化测试/本机实测覆盖（T01~T05，commit 序列 88b3270 → 0c6c60c → 36f79e1 → T05）；🌐 = 需对应真机人工回归。

1. **端到端主链路（macOS 真机，测试目标用系统应用"预览"或"备忘录"，config 白名单可配）**：
   - AnswerGate 答题通过 → 真实拉起"预览" → 使用中页显示倒计时 → 到点（用 `use_minutes = 0.1` 等 TEST 档，不真等 10 分钟）→ "预览"**被真实关闭** → AnswerGate 弹回前台 → 答题 → 通过 → "预览"**被真实重新打开** → 倒计时重新开始。
   - ✅ 后端链路：`e2e_monitor_flow::e2e_full_round_launch_countdown_kill_and_extend`（真实 PID、真实 6s 时钟到点、terminate 真杀、pgrep 交叉验证死亡、续期新 PID ≠ 旧 PID 且存活）；GUI 点击答题部分留人工/WebDriver。✅ 打包冒烟：预置 Using 状态启动 .app，日志链 `round_resume → timeout_kill(killed=true)`、目标进程真实关闭。
2. **逃避路径**：超时后不答题放置 1 分钟 → 目标软件保持关闭；答错耗尽重试 → 进入冷却，冷却重启程序不重置（沿用 P0-06 验收）。
   - ✅ `e2e_evasion_timeup_no_answer_target_stays_dead`（超时转 Quiz 后不提交，2s 复查目标仍死亡、未回 Using）；冷却不重置由 v1 回归测试覆盖。
3. **意外退出**：使用中手动关闭目标软件（Cmd+Q"预览"）→ AnswerGate 检测到进程消失 → 计时终止回到 IDLE，不误触发答题。
   - ✅ `e2e_unexpected_exit_returns_to_idle`（手动 kill 子进程 → monitor_step 探测 ProcessExited → abandon 回 Idle、纳管字段清空）。
4. **边界回归**：v1 全部 48 个测试保持绿；v2 新增计时器/进程跟踪/kill/续期逻辑有单元测试（计时器用可注入时钟 mock，避免测试真等）。
   - ✅ cargo test 全绿（80+：v1 回归 + monitor_test 8 + using_flow_test 15 + e2e 4）；MockClock 注入覆盖 remaining_sec 边界（0.1 分钟/恰好到点/负数）。
5. **家长可配**：非技术家长按文档能配出"哔哩哔哩 + 10 分钟/轮"；QA 能配出 6 秒/轮的测试档。
   - ✅ README §14.2 配置示例与 fast_test 警示；`use_minutes=0.01/-5 → 0.1` 回退有单测；fast_test 固定 10 秒有真实时钟 e2e（`e2e_fast_test_ten_second_round_times_out_for_real`）。
   - 🌐 Windows 真机：`taskkill /T /F` 进程树终止、单实例锁、关窗确认（monitor.rs 已单独验证可通过 x86_64-pc-windows-msvc 编译；打包冒烟 🌐）。

| Q1 | 超时瞬间强制动作：桌面端 kill 进程 vs 仅置顶答题页？ | **kill 进程**（默认）。置顶答题页拦不住"点回去继续看"，管控无意义；kill 后答题通过可无损重新拉起。macOS 记录 `open -a` 对应 PID 后用信号终止；Windows 按 PID/进程名终止 |

| Q5 | 超时触发的一套答题，难度/题量与首次解锁一致吗？ | 完全一致（同 config 的 question_count/pass_score），不另设"续期专用低难度"，保持规则简单、孩子无套利空间 |

## 7. 给架构师的要点提示（交接）

1. 最大技术风险：**进程跟踪与 kill**（macOS `open -a` 后取 PID、Windows 进程树终止）→ 建议竖切时最先打通"启动→取句柄→kill"三步。
2. 计时器必须 Rust 侧权威 + 持久化本轮开始时间，防"杀掉 AnswerGate 绕计时"（杀掉 AnswerGate 则失去续期能力，目标软件下轮无法被程序拉起，可接受）。
3. AnswerGate 常驻后需处理：单实例锁、托盘/最小化、窗口被关闭按钮误退出的确认逻辑。
4. QA 依赖 P0-19 加速档，请将其作为 P0 优先实现，否则端到端验收不可行。
