## AnswerGate：修复 macOS 进程句柄获取失败（核心 bug）

- 现象：答题通过拉起 B站后报 `监控失败：目标软件已启动，但未能取得进程句柄，本轮不纳管`。
- 根因：`unlock.rs` 的 `pid_via_osascript` 使用 `unix id of application "X"` 形式在本机 AppleScript 环境是**语法错误 (-2740)**，主探测器 100% 失效；pgrep 兜底未做正则转义且只匹配宽路径。
- 修复（commit 0591e20，已 push origin/main）：
  - 主路径改为精确 `pgrep -f "<app>/Contents/MacOS/<CFBundleExecutable>"`（从 Info.plist 读 CFBundleExecutable），天然排除 Helper 子进程，无需辅助功能权限；
  - `pid_via_osascript_sys` 改用 System Events tell 形式（需辅助功能权限，作为二选）；
  - 兜底 `pgrep_broad_then_validate` + ps 主进程校验；
  - `stabilize()` 做 alive + 500ms 复核；探测窗口 10s→12s（60×200ms）。
- 验证：`cargo test --lib` 13 项全绿（新增 `pgrep_exact_finds_running_process` 与 `regex_escape` 单测）；本沙箱无法拉起 GUI 应用故无法真跑 B站，已确认 B站主二进制路径为 `/Applications/哔哩哔哩.app/Contents/MacOS/哔哩哔哩`，精确模式可命中。
- 待用户在本机运行重建后的 x86_64 包做真实 B站端到端验证（辅助功能权限需重授权，因重打包签名变化）。

## AnswerGate v3：独立进程监控（watchdog）+ 10 分钟强制答题 + 「只暂停不删除」

**用户硬需求（权威口径）**：监控哔哩哔哩是否启动（不管谁启动的）→ 看视频超过 10 分钟强制答题 → 答题成功才能继续看 → **视频只暂停，不能删除** → 通过以后弹出并开始播放。

### 关键设计决策
- **watchdog 链路**：`unlock::probe_running_pid`（macOS 精确 pgrep 主二进制 / Windows tasklist）→ `commands::watch_decision` 纯逻辑判定 → `trigger_watch_intercept`（抢前台 + 暂停视频 + 开卷）→ 答对后 `gate::adopt_running` **接管既有 PID**（不重新 `open -a`，避免二次激活打断播放进度）。
- **严格档门槛**：`paper_count_for` / `pass_score_for` 按 `QuizReason` 分档；`Timeup` 与 `Watch` 都走 3 题 + 及格线 1.0（全对）。`config::sanitize` 把 `timeup_pass_score < 1.0` 强制抬回 1.0（**家长误改配置也不能放宽**）。`do_retry_quiz` 也改用 `paper_count_for`（修掉「借重试降门槛」的漏洞）。
- **只暂停不删除**：`pause_fallback_kill` 默认 false；超时/入题失败/进冷却三条路径都不 terminate 进程，由暂停守卫维持暂停态。`e2e_pause_flow::cooldown_entry_kills_paused_target_process` 已按新语义改名为 `..._keeps_paused_target_alive`。

### 踩坑与修复（重要，后续同类改动务必沿用）
1. **空格是「切换」语义，不是「暂停」语义**——重复发送会反向恢复播放。
   - v2.1 的 `spawn_paused_guard` 每 5s 无条件重发空格，会让视频一停一放，反而削弱管控。已改为 `monitor::repause_if_playing`：先用「累计 CPU 时间差值」判定是否真在播，**只在确实在播时**才补发；探测不可用时宁可不发。
   - 恢复播放同理：新增 `model::PauseState{Paused,Playing,Unknown}` 持久化在 `GateState.pause_state`，`monitor::resume_if_paused` 据此决定发不发切换键（Playing → 只置前窗口，绝不误停正在播的视频）。
   - `monitor::ensure_paused` 用于「暂停前先判定」：Playing→按 / Paused→不按 / Unknown→按。
2. **`adopt_running` 前必须先取出 `pause_state`**——`adopt_running` → `enter_using` 会把 `pause_state` 复位为 `Unknown`，顺序反了就丢信息。
3. **`reset_to_idle` 必须清 `watch_intercepted` / `watch_pid` / `pause_state`**——冷却到期回 Idle 若不清，watchdog 会因「已拦截过」永久失效（死锁）。已加回归测试 `cooldown_expiry_clears_watch_flags_so_watchdog_can_reintercept`。
4. **TOML 不允许重复 `[monitor]` 表**——写配置模板时所有 monitor 字段必须合并到同一段。
5. `include_str!("../../resources/config.toml")` 的根是**仓库根** `resources/`（不是 `src-tauri/resources/`）。
6. 默认模板新增 bilibili target 后，`command_flow` 测试的 `targets.len()` 断言从 1 改为 2；演示目标 demo-notes 的 `watch` 设 false（否则记事本一开就被拦）。

### 改动范围
- Rust：`model.rs`（`WatchMode`/`PauseState`/`TargetApp.watch`/`MonitorConfig` 6 字段）、`config.rs`、`unlock.rs`（`probe_running_pid` 4 平台实现）、`monitor.rs`（`is_playing`/`cpu_time_sec`/`parse_cpu_time`/`ensure_paused`/`repause_if_playing`/`bring_to_front`/`resume_if_paused`）、`gate.rs`（`QuizReason::Watch` + 3 个新字段 + `begin_watch_intercept`/`adopt_running`/`abandon_watch_intercept`）、`commands.rs`（watchdog 线程 + adopt + 严格档 + pause 语义）、`lib.rs`（setup 第 6 步 spawn_watchdog）。
- 前端：`types.ts`（`QuizReason` 增 `"watch"`、`RulesSummary` 增 2 字段）、`api.ts`（`onWatchIntercepted`/`onWatchAbandoned`）、`gateStore.ts`（`cameFromWatch`/`quizReason`/`handleWatchIntercepted`/`handleWatchAbandoned`、bootstrap 恢复 quiz 态）、`App.svelte`、`ResultPage.svelte`。
- 配置/文档：`resources/config.toml`（bilibili target + v3 全部配置项）、`README.md`（新增 §15，修订 §13.5/§14.2/§14.3/§14.4）、新增 `docs/PRD-v3-incremental.md`、`docs/ARCHITECTURE-v3-incremental.md`、v2 文档加后继指针。

## AnswerGate v3 本机真机验证（macOS，2026-11-04 14:10~14:35）

用户要求「本地已安装哔哩哔哩，直接启动测试」。用 `/Applications/哔哩哔哩.app` 跑了完整端到端，发现并修掉 4 个真机专属问题。

### 环境坑（本机特有，跨会话复用）
- **`/bin/ps`、`/usr/bin/top` 被系统策略整体禁用**（`operation not permitted`，setuid 提权被拒），只有 `pgrep` 可用；`dangerouslyDisableSandbox` 也绕不过（系统级限制，非 WorkBuddy shim）。TCC.db 同样受 SIP 保护无法命令行改。
- **WorkBuddy CLI 注入 `ELECTRON_RUN_AS_NODE=1`**：任何 Electron 应用（B 站）被启动都会以 Node 模式跑一句 "Welcome to Node.js" 后立即退出。**必须用 `unset ELECTRON_RUN_AS_NODE` + `export NODE_OPTIONS=''` 后直接执行主二进制**，而且 `open -a` 也不行。
- B 站真实信息：`mac=/Applications/哔哩哔哩.app`（不是模板里写的 `bilibili.app`）、`CFBundleExecutable=哔哩哔哩`、`CFBundleIdentifier=com.bilibili.bilibiliPC`。精确 pgrep 命中主进程，Helper 在 `Contents/Frameworks/` 下天然排除 ✓。
- **vite 监听 IPv6 `::1`**，`127.0.0.1` 端口探测会假超时；要同时探 `::1` 与 `127.0.0.1`。
- 运行时配置目录：`~/Library/Application Support/com.answergate.app/`（config.toml / .answergate_gate_state.json / logs/）。测试前必须删 gate_state.json 让相位回到 Idle，否则 watchdog 判定不命中。

### 本轮修的 4 个真机问题（均已入库）
1. **`ps` 禁用导致 watchdog 完全失效** → `unlock::is_main_app_process` 改三态 `Option<bool>`（`ps` → `pgrep -fl` → 采信精确路径命中）；`probe_running_pid` 主进程判定改用 match 三态。
2. **`ps` 禁用导致 `is_playing` 恒 None** → `monitor::cpu_time_sec` 加 **libproc `proc_pidinfo(PROC_PIDTASKINFO)` 兜底**。关键实测：内核写入 **96 字节**（给 48 会返回 0），CPU 时间在 u64 数组下标 2/3（纳秒）；「自旋 1.5s → delta 1.386s」验证精度。加了 2 个单测。
3. **日志被杀全丢** → `log.rs` 去掉 `non_blocking`（默认攒 128 行才刷盘），改同步写，每条立即落盘；`lib.rs` 去掉 `mem::forget(guard)`。改完立刻能看到 `watch_detected` 等日志。
4. **辅助功能权限缺失时管控静默失效** → 新增 `gate://permission-required` 事件 + 前端 `permissionWarning` 顶部常驻告警条；`handle_timeout` 与 `trigger_watch_intercept` 在 `PauseState::Unknown` 时推送。

### CPU 阈值实测与校准
- 首页稳定态（无播放）主进程 1s 增量：`0.040 / 0.040 / 0.040 / 0.119 / 0.072`；整树 `0.167~0.278`。
- 冷启动加载期：主进程最高 `0.844`，整树 `1.143`。
- 原阈值 `0.12` 贴着空闲峰值 `0.119` 必误判（守卫会反向恢复播放）→ **上调为 `0.25`**（`monitor.rs::CPU_BUSY_THRESHOLD_SEC`）。
- ⚠️ 播放态增量尚未测（缺权限无法真正暂停做 A/B），授权后若「播放中守卫不动作」需下调。
